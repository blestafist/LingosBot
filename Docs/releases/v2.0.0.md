## LingosBot 2.0 — a web workspace for your lessons

LingosBot 2.0 adds a multiuser WebUI and a standalone Rust HTTP worker alongside the existing desktop application. Run lessons, collect vocabulary, manage schedules and follow progress from one place, without a browser automation dependency in the server workflow.

### New WebUI

- **Your own workspace:** separate Lingos credentials, classes, settings, vocabulary, schedules and run history for each user. Administrators manage accounts; there is no public registration.
- **Live runs:** start or stop a task, follow lesson progress and revisit saved results after closing the tab. Dashboard's Run now can override the default lesson count for one run without changing saved settings; per-class overrides still take priority.
- **Flexible scheduling:** choose a time, weekdays and timezone, or use a five-field cron expression. See the next automatic run and skip just that occurrence without disabling later runs.
- **Vocabulary library:** collect words from all classes without completing lessons. The library updates only after collection succeeds. Browse and search wordsets, then export selected sets together as Markdown or JSON.
- **Account controls:** verify saved Lingos credentials without starting lessons. Administrators can disable or permanently remove users, with safeguards for active tasks and the last enabled administrator.
- **A refreshed interface:** an English Material 3 Expressive-inspired design, responsive navigation, light/dark/system appearance and locally bundled fonts. No CDN scripts, external fonts or analytics.

### Optional Telegram notifications

- Link a private Telegram chat using a short-lived, one-use code from Account.
- Enable run-result notifications separately; they are **off by default**. Notifications cover finished lessons, credential verification/class sync and vocabulary collection, not a live progress stream.
- Disconnect from Account or with `/stop`. Administrators can view all connections and disconnect them, but cannot opt users into notifications.
- The bot runs inside the WebUI server using outbound long polling: no public webhook or separate bot process is required. It cannot start or stop lessons.

### Standalone Rust worker

- A browser-free Linux CLI for authentication, classes, vocabulary, challenges and lessons over HTTP, with no .NET runtime or database requirement.
- Static musl binaries for x86_64 and ARM64, plus structured JSON results and realtime events for integrations.
- Strict response validation and safety/time limits: unknown or unconfirmed states stop the run instead of being guessed or silently retried.

Each asset has a `.sha256` checksum. WebUI binaries include frontend assets but need the matching worker, trusted system CA certificates and the environment settings described in [WebUI setup](https://github.com/blestafist/LingosBot/blob/v2.0.0/docker-webui/README.md). The desktop archives remain self-contained and include Selenium Manager for optional browser mode.

### Upgrading and compatibility

- **Desktop behavior is unchanged from v1.5.1-beta.1.** Its source now lives in `worker-desktop/`; update source-build scripts and project paths accordingly. The Rust worker is a separate CLI, not a drop-in replacement for desktop flags or configuration. See the [worker guide](https://github.com/blestafist/LingosBot/blob/v2.0.0/worker-server-rust/README.md).
- **Back up before upgrading an existing WebUI:** stop the server and save the entire data directory and the original `ENCRYPTION_KEY`. Reuse that key; replacing it makes stored Lingos passwords unreadable. Legacy migration preserves the original administrator's credentials and daily schedule and invalidates old sessions.
- **Configure secrets on the server.** `ADMIN_USER`/`ADMIN_PASSWORD` bootstrap the first administrator. `TELEGRAM_BOT_TOKEN` is optional. Local launches do not automatically read `.env`; Docker Compose does. Keep the database outside temporary directories and never commit secrets.
- **Use HTTPS for remote access**, with secure cookies and a properly configured reverse proxy. Local HTTP is for loopback development only. See the [security and deployment notes](https://github.com/blestafist/LingosBot/blob/v2.0.0/docker-webui/SECURITY-AUDIT.md).

### Operating limits

- This is a single-server application with one active worker task at a time across all users. The server must be running for schedules to execute; downtime does not replay a backlog of missed lessons.
- Stopping a task cannot undo completed lessons or requests already accepted by Lingos. Interrupted runs are not automatically retried; check Lingos before restarting them.
- Telegram delivery is best-effort: an uncertain send can produce a duplicate, and an already in-flight message can arrive after disconnecting.
- Automated checks do not certify a production deployment. Validate your own HTTPS/proxy configuration and target platform before exposing the service. Automate only accounts you are authorized to use and review Lingos's terms.

### Release delivery

CI checks Rust, desktop and WebUI, builds all eight downloadable assets and their checksums, then creates a **draft** only for a release tag whose commit is already in `main`. Publishing remains a separate manual approval.
